Home Procedure Player Storage Results Hosts

Procedure

Run these in order. Write what you see on the results page, and keep the player log with that export (Copy, Share, or Download). If it is not on the screen, it is not in the result.

The allowlist entry for this site is exactly tenderfern.github.io. Never list github.io. Listing github.io would allow every site published on GitHub Pages. The pages are at https://tenderfern.github.io/ipad-check/.

Before you start

  • On the home page, type the iPadOS version from the Settings page that lists the software version. iPadOS Safari reports a Mac user agent by default, so the user agent is not that version.
  • Note whether the video app is installed.
  • On a desktop browser, capture a HAR while each test video plays in each mode. The hosts page says how, and it turns the file into a host list. Do not commit the HAR. A HAR can hold cookies and headers. Commit the host list, inside the results note.

A — Baseline, no restrictions

Use the setting that does not limit which websites can open. If a limit is already on, turn off the control that blocks every website except the ones you list.

For every video in the set, in every mode, with the guard off and then with the guard on, record what plays, what fails, and which error the log names.

  • The made-for-kids video and the long monetized video are the ones that should play while the network is open.
  • The embedding-disabled id should fail. Expect error 101 or 150.
  • The missing id should fail. The player API reference names error 100 when a video is not found. A desktop API load of the id in this set logged 150, and the frame said Video unavailable. Write down the code the iPad log shows.
  • The age-restricted video should refuse or send you away.

Then, with the guard off, on the creator video (set the start near the end if you want to get there quickly):

  1. Question 4. What the player shows in its last seconds and after the video ends. What a tap on those elements does. Whether a tap loads another video in the same player, and whether the log shows that in time. What changes in fullscreen. Use the player's own fullscreen control.
  2. Question 5. Where a tap on the title, the channel, the logo, and any Watch on YouTube link goes: a new tab, the page shown for a website that is not allowed, or the video app if it is installed.
  3. Question 6. Which events, states, and errors the log shows, for each case and each mode.

The guard removes the player when the video ends or the id in the player changes. Leave it off while you are looking at the end of a video, or at an ad.

B — Allowlist

Turn on the Screen Time control that allows only websites you list and blocks every other website. Its label changes between iPadOS versions. Use the control that does that, not a control that only hides adult sites and still opens everything else.

Start the list with tenderfern.github.io alone. Open this site and try every mode. Record what fails.

Then add hosts one at a time. After each addition, try every mode and record what plays and what fails. Use this order:

  1. www.youtube-nocookie.com
  2. i.ytimg.com
  3. googlevideo.com — a host ending in googlevideo.com counts. Write the exact host the player asked for.
  4. The rest of the HAR list, one at a time, except www.youtube.com.
  5. www.youtube.com last, and only to learn what it changes. Listing it would open the video site itself.

The result is the smallest list on which each mode plays. That answers questions 1 and 2. Question 2 is whether the API script loads, and whether any mode plays, before www.youtube.com is added. The script is requested from www.youtube.com. The plain iframe does not request it.

C — Ads

On the smallest list that plays the monetized video, play that video several times with the guard off. Record whether ads play. Take the ad hosts from a desktop HAR captured while that video plays, not by blocking anything.

If those hosts are on the allowlist, remove them and play again. Record whether playback survives. That answers question 3. The pages do not block ads.

D — Pairing

Open the storage page in a Safari tab and write a token. Then use the share-sheet action that adds the current page to the Home Screen as its own icon, and open the page from that icon. A tab and a home-screen web app do not share storage, so write down whether the tab's token is absent there, and write a token in the web app too.

Revisit both after about one day, three days, and eight days. Safari can delete a site's script-written storage after seven days without a visit. Record which copies are still there and how old they are. That answers question 7.

The storage page cannot set an HttpOnly cookie. GitHub Pages has no server that can set one. A token that survives here is a lower bound: the product's own server could use an HttpOnly cookie.

What to save

On the results page, export Markdown with the log attached. Save the file in this repository as results/<date>-<device>.md, for example results/2026-10-03-ipad.md.
